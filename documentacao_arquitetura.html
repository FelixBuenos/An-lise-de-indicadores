1. Visão Geral e Estilo Arquitetural

O Portal de Indicadores foi construído sob o paradigma moderno da JAMstack (JavaScript, APIs, Markup), combinado com uma arquitetura Multi-Page Application (MPA) Componentizada.

┌─────────────────────────────────────────────────────────────────────────────┐ │ NAVEGADOR CLIENTE │ │ │ │ [index.html] [demandas.html] [graficos.html] [painel.html] │ │ │ │ │ │ │ │ [main.js] [demandas.js] [graficos.js] │ │ │ │ │ │ │ │ │ [Observer / Componentes] │ │ │ │ │ │ │ │ │ │ │ └──────────────────────┴─────────────────────┴────────────────┘ │ │ │ │ │ ▼ (HTTPS / WSS Realtime) │ └──────────────────────────────────────┬──────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ BACKEND AS A SERVICE (SUPABASE CLOUD) │ │ │ │ ┌───────────────────────┐ ┌──────────────────────┐ ┌──────────────────┐ │ │ │ PostgREST API Engine│ │ Auth & JWT Security │ │ Realtime Engine │ │ │ └───────────┬───────────┘ └──────────┬───────────┘ └────────┬─────────┘ │ │ └─────────────────────────┼───────────────────────┘ │ │ ▼ │ │ BANCO DE DADOS POSTGRESQL 15 │ │ (dados_lojas, tabela_completa, lojas_ferramenta, demandas, gestores) │ └─────────────────────────────────────────────────────────────────────────────┘

Por que não usar um Framework Pesado (ex: React, Angular)?

Em projetos de inteligência operacional com tabelas densas e leitura de alta frequência, a escolha de JavaScript Vanilla ES6+ oferece vantagens críticas:

  • Desempenho Extremo (Zero Overhead): Sem Virtual DOM consumindo CPU/RAM, o navegador renderiza as matrizes de dados diretamente no DOM nativo.
  • Carregamento Instantâneo: O tamanho total dos arquivos transferidos é inferior a 150 KB (contra mais de 1.5 MB de bundles React/Angular).
  • Longevidade e Manutenibilidade: Sem dependências que sofrem depreciação constante de versões (zero risco de quebra por updates de bibliotecas terceiras).

2. Árvore de Diretórios e Separação de Camadas

O projeto segue o princípio de Separação de Responsabilidades (Separation of Concerns - SoC), onde cada pasta possui um papel estrito:

🎨 1. Camada de Estilos (css/)

css/globais/: Contém o Design System central (variaveis.css define a paleta corporativa Conviva, tipografia e sombras; base.css aplica reset e scrollbars; layout.css gerencia o grid principal).
css/componentes/: Estilos atômicos e isolados de cada tabela, header, filtros, diagnóstico e modais.
css/paginas/: Estilos específicos das rotas de entrada (painel, login, gráficos, demandas).

🧠 2. Camada de Infraestrutura e Serviços (js/servicos/)

supabaseClient.js: Ponto único de comunicação com o Supabase. Garante reuso de conexão.
FiltroObserver.js: Barramento de eventos que sincroniza os filtros com as tabelas.

⚙️ 3. Camada de Domínio e Componentes (js/componentes/)

tabela-principal.js: Monta a matriz retroativa de 5 semanas da filial.
tabela-media.js: Processa o cálculo cruzado de média da classe com segmentação por ferramenta (Analysis vs Pricing).
diagnostico.js: Motor de inteligência operacional que compara KPIs e gera os pontos fortes e de atenção.
demandas.js: Módulo CRUD com controle de acesso granular baseado em autor e perfil de gestor.

3. Padrões de Projeto (Design Patterns) na Prática

A. Observer Pattern (Padrão Observador)

O Observer resolve o problema de comunicação entre componentes desconectados. Quando o usuário troca a loja ou semana na barra de filtros, não chamamos cada tabela manualmente; em vez disso, o filtroObserver notifica todos os ouvintes inscritos:

// js/servicos/FiltroObserver.js
class FiltroObserver {
    constructor() {
        this.ouvintes = [];
    }

    inscrever(funcao) {
        this.ouvintes.push(funcao);
    }

    notificar(dados) {
        this.ouvintes.forEach(funcao => funcao(dados));
    }
}

export const filtroObserver = new FiltroObserver();
// main.js - Inscrição Desacoplada dos Componentes
filtroObserver.inscrever((dados) => {
    preencherTabelaPrincipal(supabase, dados.filial, dados.periodo);
});

filtroObserver.inscrever((dados) => {
    renderizarDiagnostico(supabase, dados.filial, dados.periodo);
});

B. Singleton Pattern (Instância Única)

O Singleton assegura que apenas um objeto do cliente Supabase exista durante toda a execução da aplicação, evitando o esgotamento de conexões no plano gratuito:

// js/servicos/supabaseClient.js
import { createClient } from 'https://cdn.jsdelivr.net/npm/@supabase/supabase-js/+esm';

const supabaseUrl = 'https://zhfisczfrmhxeegcvvto.supabase.co';
const supabaseKey = '...';

// Exporta uma única instância constante compartilhada
export const supabase = createClient(supabaseUrl, supabaseKey);

C. Role-Based Access Control (RBAC) em Camada de Aplicação

Em demandas.js, implementamos uma checagem de autorização em dois níveis (Front-end e Banco):

  • Autor da Demanda: demanda.analista === usuarioLogado → Permite Editar, Concluir e Excluir.
  • Administrador Geral: Presente na tabela gestores → Permissão irrestrita sobre todas as demandas.
  • Terceiros: Exibição do badge 🔒 Somente Leitura e bloqueio de cliques.

4. Modelagem de Dados & Otimização no PostgreSQL

As tabelas foram modeladas para garantir integridade e leituras pontuais rápidas:

Tabela Chaves Principais Finalidade
dados_lojas filial, data_final Armazena os indicadores semanais (Venda Líquida, Qtd Clientes, Ticket, CMV, Falta, Desconto).
lojas_ferramenta_desconto loja Mapeia qual ferramenta de desconto (ANALYSIS ou PRICING) a loja opera.
tabela_completa filial, status, data_final Histórico geral da rede usado para calcular a média de desconto entre lojas da mesma classe e ferramenta.
meta_cluster cluster Metas ideais de mercado (CMV <= 63%, Desconto <= 30%, Falta <= 9%, Ticket >= R$ 50,00).
demandas id, loja, analista Gestão de planos de ação, prazos, prioridade e status de conclusão.
⚡ Otimização Free Tier: As consultas utilizam projeções restritas, ordenação indexada por data_final DESC e limites de paginação (.limit()), mantendo o consumo de banda mensal abaixo de 5% da cota gratuita.

5. Motor do Diagnóstico Semanal (Inteligência de Negócios)

O módulo diagnostico.js processa regras de negócio no próprio navegador do cliente:

[Entrada: Loja + Semana Atual] ──► [Busca 5 Semanas Retroativas + Histórico] │ ▼ [Localiza Mesma Semana do Mês Anterior] (Calcula ~28 dias antes no histórico) │ ▼ [Avaliação Multicritério de 10 KPIs] │ ┌─────────────────────────────────┴─────────────────────────────────┐ ▼ ▼ [Indicador Melhorou / Meta OK] [Indicador Recuou / Fora da Meta] │ │ ▼ ▼ 🟢 PONTOS FORTES DA SEMANA 🔴 PONTOS DE ATENÇÃO & DESVIOS (Cards com Delta % e Nominais) (Cards com Desvios e Alertas)

Os 10 KPIs Monitorados:

  1. Venda Líquida: Faturamento e crescimento percentual vs período comparado.
  2. Quantidade de Clientes: Atendimentos e variação nominal de fluxo.
  3. Ticket Médio: Gasto médio por atendimento (Meta: ≥ R$ 50,00).
  4. Itens por Cliente: Cesta média de produtos (Meta: ≥ 2,50).
  5. CMV (Custo da Mercadoria): Margem e custo dos produtos (Teto: ≤ 63,0%).
  6. Desconto: Concessão de desconto comercial (Teto: ≤ 30,0%).
  7. Falta de Produtos (Ruptura): Nível de desabastecimento em loja (Meta: ≤ 9,0%).
  8. Aproveitamento Promocional: Adesão aos encartes e ofertas (Meta: ≥ 60,0%).
  9. Cobertura de Estoque: Dias de estoque disponível (Calibragem: 45 a 60 dias).
  10. EAS (Salão de Vendas): Índice de eficiência visual e operacional (Meta: ≤ 20,0%).

6. Confiabilidade e Melhores Práticas de Engenharia

A. Cache-Busting Contínuo (?v=XX)

Navegadores realizam cache agressivo de arquivos JavaScript e CSS. Para garantir que todos os colaboradores recebam as atualizações sem precisar limpar o histórico, aplicamos versões dinâmicas em todas as importações:

<script type="module" src="main.js?v=85"></script>
<link rel="stylesheet" href="css/componentes/diagnostico.css?v=61">

B. Código Defensivo e Tolerância a Falhas

  • Optional Chaining (?.): Evita erros de TypeError: Cannot read property of undefined em elementos ausentes.
  • Operadores de Coalescência Nula (|| '-'): Garante que dados nulos do banco não quebrem as tabelas.
  • Sanitização e Conversão Numérica (normalizarPercentual): Trata automaticamente números salvos como 0.25 ou 25%.
